# 운영 가이드 (관리자용)

- 사이트: https://knucse-lol.vercel.app/group/main
- 관리 화면: https://knucse-lol.vercel.app/group/main/admin
- 상태 점검: https://knucse-lol.vercel.app/api/health
- 호스팅: **Vercel** 프로젝트 `knucse-lol` (GitHub `master` 에 푸시하면 자동 배포) · DB: **Supabase** (서울 리전)

> 비밀값(키·비밀번호)은 Vercel/Supabase 화면에만 입력하세요. 채팅·이슈·커밋에 붙여넣지 않습니다.

---

## 1. 환경변수 (Vercel → Settings → Environment Variables)

| 이름 | 값 | 비고 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL (`https://xxxx.supabase.co`) | 공개값. 끝에 `/rest/v1/` 이 붙어 있어도 자동으로 바로잡음 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase **anon / publishable** 키 | 공개값. DB 설정상 조회만 가능 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase **service_role / secret** 키 | **비밀**. 앞에 `NEXT_PUBLIC_` 을 붙이면 안 됨 |
| `ADMIN_PASSWORD` | 직접 정한 값 (8자 이상) | **비밀**. 웹에서 기록 수정 |
| `UPLOAD_SECRET` | 직접 정한 값 (8자 이상, ADMIN_PASSWORD 와 다르게) | **비밀**. 수집기 업로드 토큰 |

값을 바꾸면 **Deployments → 최신 배포 ⋯ → Redeploy** 해야 반영됩니다.
비밀값 만들기 (Windows PowerShell):

```bash
$b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); ($b | % { $_.ToString('x2') }) -join ''
```

## 2. 처음부터 다시 배포할 때

1. Supabase 새 프로젝트 → **SQL Editor** 에서 순서대로 실행 (모두 여러 번 실행해도 안전)

   | 순서 | 파일 | 결과 |
   |---|---|---|
   | 1 | [`supabase/01_schema.sql`](../supabase/01_schema.sql) | 테이블·권한(읽기 전용 RLS) |
   | 2 | [`supabase/02_restore_28_matches.sql`](../supabase/02_restore_28_matches.sql) | 6/4~7/2 수기 28경기 → 마지막 줄 `28` |
   | 3 | [`supabase/03_excluded_matches.sql`](../supabase/03_excluded_matches.sql) | 기록 제외 기능 + 10/26 Zeus's Law 지정 → `1` |

2. 그 뒤 데이터는 **관리 화면 → 경기 자료 가져오기** 에 최근 백업 파일을 넣어 복원합니다 (아래 3장).
3. Vercel 에서 저장소 Import → 환경변수 5개 → Deploy.
4. `/api/health` 가 `"ok": true`, `"anonWriteBlocked": true` 면 정상.

## 3. 백업과 복원

- **백업**: 관리 화면 → *1. 백업 내보내기* → `naejeon-backup-YYYY-MM-DD.json` (경기·참가자 스탯·선수 정보·기록 제외 표시 전부)
- **복원**: 같은 화면 *2. 경기 자료 가져오기* 에 백업 파일 → 미리보기 확인 → **DB에 반영**. 이미 있는 경기는 건너뛰므로 여러 번 넣어도 중복되지 않습니다.
- Supabase 무료 플랜은 자동 백업이 없습니다. **내전한 날이나 한 달에 한 번** 내려받아 두세요.
- 아이디 통합·대량 가져오기처럼 되돌리기 어려운 작업 전에는 먼저 백업하세요.

## 4. 자주 하는 작업

### 경기 기록에서 빼기 ("없던 경기", 예: *Zeus's Law*)
경기 상세 → **기록 제외** → 표시할 문구 입력. 해제는 **제외 해제**.
지우지 않고 흑백 + 흰 글씨로 남으며, 경기 수·모든 통계·어워즈·팀 밸런스에서 빠집니다.

### 아이디 통합 (같은 사람이 두 닉네임으로 집계될 때)
**선수 정보 → 아이디 통합** → 본캐(남길 이름)·부캐(합칠 이름). 부캐의 모든 경기가 본캐로 옮겨지고, 부캐는 이후에도 자동으로 본캐로 집계됩니다.
- 보통 **최근에 쓰는 이름을 본캐**로 둡니다.
- 합치기 전에 두 이름이 **같은 판에 함께 나온 적이 없는지** 확인하세요 (같이 나왔다면 다른 사람).
- 되돌리려면 백업에서 복원해야 하므로 먼저 백업.

### 과거 내전 가져오기 (롤 클라이언트 전적)
1. 롤 로그인(로비 화면) → 수집기 **과거 경기 가져오기 → 경기 불러오기**
   (10명이 5대5로 한 협곡 커스텀만 목록에 남고, 봇전·1대1 등은 자동 제외)
2. 아무것도 선택하지 않고 **선택한 경기 JSON 저장** → `%APPDATA%\naejeon-collector\history_export_….json`
3. 관리 화면 **경기 자료 가져오기** 에 넣기 → 미리보기 숫자 확인 → **DB에 반영**

미리보기에서 보는 숫자:

| 항목 | 뜻 |
|---|---|
| 추가 | 새 경기 |
| 갱신 | 같은 gameId 가 이미 있어 내용 갱신 |
| 수기 기록에 합침 | 수기 28경기와 10명 챔피언·KDA 가 같아 자동으로 합침 (닉네임은 기존 표기 유지) |
| 건너뜀 | 이미 있는 경기 |
| 중복 후보 | 비슷하지만 확실하지 않아 보류 → *3. 중복 후보 검토* 에서 합치기/따로 등록/버리기 |
| 오류 | 읽을 수 없거나 내전이 아닌 자료 (반영하지 말고 확인) |

클라이언트는 **로그인한 계정이 참가한 경기만**, 보관 기간까지만 돌려줍니다. 빈 기간(현재 7/3~9/11)은 그 기간에 뛴 다른 참가자가 같은 방법으로 뽑아 주면 채울 수 있습니다.

### 예전 경기에 아이템·룬·오브젝트 채우기
새 수집기로 **과거 경기 가져오기 → JSON 저장** 을 다시 하고 관리 화면에 넣으면, 같은 gameId 경기가 **갱신**되며 아이템·주문·룬·팀 오브젝트가 채워집니다 (닉네임·기록 제외 표시는 그대로). 수기 28경기에는 원본 자료가 없어 채울 수 없습니다.

### 수동 등록
상단 **수동 등록** — 단톡·디스코드 결과표를 옮길 때 경기 날짜를 지정합니다. 모르는 딜량·시야는 비워 두면 *미수집* 처리.

### 수집기 나눠 주기
관리 화면 맨 위 **토큰 포함 수집기 내려받기** → 받은 ZIP 을 내전하는 사람에게 전달 → 각자 압축 풀고 `내전수집기.bat` 더블클릭.
그날 참가자 중 한 명만 켜져 있어도 경기가 올라가므로, 자주 하는 사람 여러 명에게 깔아 두면 됩니다 (같은 경기는 한 번만 기록).
ZIP 에 업로드 토큰이 들어 있으니 아무에게나 주지는 마세요 (토큰으로는 추가만 가능, 수정·삭제 불가).

### 수집기 토큰 바꾸기
Vercel 의 `UPLOAD_SECRET` 변경 → Redeploy → 수집기 쓰는 사람들이 **업로드 토큰 설정** 에 새 값 입력.
관리자 비밀번호(`ADMIN_PASSWORD`)를 바꿨다면 그 값을 저장해 둔 도구(브라우저 로그인, 자동화 도구 등)도 새 값으로 바꿔야 합니다.

## 5. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 사이트에 "기록을 불러오지 못했습니다" | Supabase 무료 프로젝트가 오래 접속이 없어 **일시 중지**됐을 가능성. Supabase 대시보드에서 **Restore**. 데이터는 지워지지 않음. (매일 03:17 KST 에 Vercel Cron 이 `/api/health` 를 호출해 DB 를 깨워 두므로 보통은 일어나지 않음 — `vercel.json`) |
| `/api/health` 의 `anonWriteBlocked: false` | `01_schema.sql` 이 끝까지 실행되지 않았거나, anon 칸에 service_role 키를 넣음. SQL 재실행 후 환경변수 확인 |
| `Invalid path specified in request URL` | Supabase 주소에 경로가 붙음. 현재 코드는 자동으로 바로잡으므로 최신 배포인지 확인 |
| 기록 제외 시 "excluded_reason 열이 없습니다" | `03_excluded_matches.sql` 미실행 |
| 수집기 "토큰이 서버의 UPLOAD_SECRET 과 다릅니다" | 토큰 오타 또는 서버 값 변경 → 다시 입력 |
| 수집기 과거 경기 조회 `HTTP 에러: 500` | 클라이언트가 큰 범위 요청을 거부한 경우 — 최신 수집기는 자동으로 작은 범위로 재시도. 그래도 안 되면 **진단** 버튼 결과를 확인 |
| 관리 화면 로그인 비밀번호를 잊음 | Vercel 환경변수 `ADMIN_PASSWORD` 확인 (Sensitive 로 저장했으면 새 값으로 바꾸고 Redeploy) |
